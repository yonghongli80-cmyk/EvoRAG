# Real Model P99 Acceptance Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to execute each task and review evidence.

**Goal:** 采集不影响现有服务与业务数据的真实模型 P99 基线，按证据决定优化。
**Architecture:** 独立源码副本/合成资料/存储/临时认证，真实远程模型；主代理唯一发压与生命周期所有者。
**Tech Stack:** Python3.12生产锁环境、真实FastAPI/uvicorn、httpx、Qdrant local、新合成SQLite。
**Spec:** docs/superpowers/specs/2026-10-24-real-model-p99-design.md

## Global Constraints
- main a448d25；隔离分支codex/real-model-p99-2026-10-24，原8080和原业务数据不操作。
- 真实模型/检索配置选择性内存载入，密钥不进argv/文件/输出；不复制业务.env。
- 新副本正常lifespan；禁用backup/evolution/candidate/material worker/Redis。
- 先6条串行试跑和2条预热；测量最多200条、并发≤2、启动≤12/分钟、HTTP超时120s。
- 429/认证计费错误停止；原服务两次探测失败或PID改变停止；全部失败/未完成样本留痕。
- 不设SLO通过线；200样本P99有限，不能冒充饱和容量/真实业务质量验收。
- 公司工作记录由主代理统一实际submit，子代理不另记；不使用computer use。
- 不额外全量回归；临时验收工具做有效控制，产品修复则RED/GREEN及必要回归。
- 本轮先形成可审结果；不重新部署原服务。主代理统一提交文档，避免子代理并发git操作。

## Review Focus
- 路径/凭据隔离，在启动自动迁移/索引前核对。
- HTTP200但无生成/错答案/空引用必须按质量失败，不能假成功。
- 模型调用被缓存或降级时单独标记，不能冒充真实生成。
- 失败、超时、上游限流不从分母/尾部静默剔除；原始样本与摘要一致。
- 进程PID及端口属于本轮，清理不操作原8080或全局Docker/模型服务。
