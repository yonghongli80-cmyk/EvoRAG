# RAGv3 销售、项目与数据分析助手设计

## 1. 目标

本阶段在同一助手平台上增加销售资料、项目和数据分析三类助手。它们复用已有权限、版本、可靠性、引用、结构化查询、收藏、历史、通知和审计。

## 2. 前置条件

开始普通功能实施前必须完成：

- 可信知识闭环。
- 回答可靠性与结构化数据查询网关。
- 员工体验中的收藏、通知和历史。
- 助手配置与 Workflow 运行时。

销售、项目和普通经营表格功能可以使用虚构或非敏感数据先开发。企业治理中的能力权限和审计基础是公司范围上线的前置条件；工资、考勤等严格受限数据还必须经过主管确认。如果某个前置能力延后，本阶段不得在助手内部临时复制它。

## 3. 销售资料助手

### 3.1 数据范围

- 当前产品资料。
- 标准报价说明。
- 案例和演示资料。
- 经批准的销售话术。
- 合同模板和交付边界说明。

客户私有资料必须位于独立知识库并使用客户／项目 ACL，不能与公司通用销售资料自动混合。

### 3.2 能力

- 根据客户场景推荐资料。
- 生成沟通提纲。
- 生成方案和邮件初稿。
- 比较产品版本或套餐。
- 检查草稿是否缺少必要说明。
- 输出使用资料清单。

所有生成内容标记“内部草稿”。助手不得：

- 承诺未被资料支持的价格、折扣、交付日期或功能。
- 自动发送邮件或消息。
- 自动修改 CRM、合同或报价。
- 引用用户无权访问的客户案例。

### 3.3 Workflow

```text
识别客户场景
→ 检索当前产品和交付边界
→ 必要时比较候选方案
→ 生成结构化草稿
→ verifier 检查每项承诺的引用
→ 标记无依据或需人工确认项
```

只有“完整方案报告”启用 planner、evidence worker、verifier；普通资料问答使用单 Workflow。

## 4. 项目助手

### 4.1 项目空间

项目助手使用现有知识库加项目元数据：

- 项目 ID、名称、状态。
- 项目知识库。
- 项目负责人。
- 开始、结束和归档时间。
- 允许的助手工具。

项目成员资格不在本阶段自动从钉钉同步，由现有用户和权限配置维护。

### 4.2 数据范围

- 需求和设计。
- 会议纪要。
- 决策记录。
- 周报和里程碑。
- 风险和复盘。

### 4.3 能力

- 汇总本周变化。
- 从会议纪要提取候选待办。
- 汇总风险和阻塞项。
- 生成带引用的周报草稿。
- 比较需求或方案版本。
- 项目结束后生成复盘草稿。

提取到的待办默认是“建议”，用户确认后才写入项目待办。助手不自动给其他员工分配任务。

### 4.4 归档

项目结束后：

- 项目助手切换为只读。
- 保留引用和历史。
- 停止普通更新订阅，发送一次归档通知。
- 新增资料需要项目负责人重新开启或创建后续项目。

归档不自动开放给其他项目，也不删除原成员历史权限记录。

## 5. 数据分析助手

### 5.1 定位

数据分析助手是阶段 1 结构化查询网关的用户入口，不是一个可以执行任意 Python／SQL 的通用 Agent。

### 5.2 能力

- 数据集和工作表发现。
- 字段说明。
- 筛选、计数、去重、求和、平均、最小和最大。
- 按维度分组。
- 同比、环比和时间趋势。
- 基于确定规则的异常值识别。
- 受限图表生成。
- 多数据集比较。

第一版不支持：

- 任意代码。
- 任意 SQL。
- 机器学习模型训练。
- 自动修改源 Excel/CSV。
- 从图表反写结论到原文件。

### 5.3 查询计划

模型生成 `StructuredQueryPlan`，服务端校验后执行。计划明确：

- 数据集版本。
- 工作表。
- 字段。
- 过滤条件。
- 指标和维度。
- 时间范围。
- 排序和限制。
- 图表类型。

结果保存可重放计划和数据引用。文件更新后重新运行使用新版时，UI 明确提示版本变化。

### 5.4 多表比较

跨表计算前检查：

- 列语义映射。
- 数据类型。
- 单位。
- 时区和日期粒度。
- 去重键。
- 统计口径。

不一致时要求用户确认映射；不得仅因列名相似就自动合并。比较结果显示每个数据集的文件版本和参与行数。

### 5.5 图表

允许折线、柱状、堆叠柱状、饼图和散点图。后端只接收已验证的数据序列和样式枚举，不允许模型指定输出路径或执行绘图库代码。

图表文件使用不可预测 ID、短期下载令牌和当前用户权限检查。审计记录数据集和字段，不记录敏感明细。

## 6. 工资与考勤功能闸门

代码可以实现工资、考勤的结构化查询，但生产默认：

```text
sensitive_structured_query_enabled = false
```

开启条件：

- 主管确认允许处理的数据类型。
- 明确 `hr_data_analyst` 名单。
- 确认外部模型可接收的数据范围。
- 完成虚构数据测试和审计验证。
- 明确导出、图表和聚合限制。

开启后仍遵守：

- 系统管理员没有默认明文权。
- 现有通用 SQL Agent 不访问敏感数据集。
- 明细使用后端固定模板。
- 脱敏聚合是否进入外部模型由策略决定。
- 真实查询全部写入治理审计。

如果主管未批准，本助手仍可分析普通销售、项目和运营表格，不影响其他功能上线。

## 7. 统一 UI

三类助手作为助手选择器和首页卡片出现：

- 销售资料助手。
- 项目助手。
- 数据分析助手。

不增加三个独立主导航页面。不同助手可以提供自己的起始表单：

- 销售：客户场景、产品、输出类型。
- 项目：项目、时间范围、报告类型。
- 数据：数据集、问题、图表开关。

提交后仍进入统一聊天消息流，输出使用统一引用、置信度、收藏和反馈组件。

## 8. API 与工具

复用 `/assistants/{key}/query`。新增领域工具：

- `sales_material_search`
- `sales_draft_builder`
- `project_change_summary`
- `project_action_candidate_extractor`
- `project_risk_summary`
- `structured_dataset_discovery`
- `structured_query`
- `structured_chart`

每个工具通过注册表声明能力、输入输出 schema、模型可见范围、最大数据量和审计事件。

领域工具不直接暴露数据库连接、文件路径或原始凭据。

## 9. 质量和人工确认

以下输出必须显式确认才能进入后续业务：

- 销售承诺和报价草稿。
- 项目待办和负责人。
- 项目风险关闭。
- 多表字段映射。
- 敏感数据导出。

确认动作记录用户、原草稿、修改后内容和引用版本。系统不会把“模型生成”冒充“负责人批准”。

## 10. 失败与降级

- 销售资料冲突：并列展示并阻止确定性承诺。
- 项目资料缺日期：报告中列为“时间未知”，不归入具体周期。
- 待办提取失败：保留会议纪要引用，不创建空任务。
- 数据集 schema 改变：旧查询计划失效并要求重新确认。
- 图表失败：仍返回表格结果和计算口径。
- 外部模型不可用：结构化计算可返回模板结果。
- 多 Agent 超时：返回每个已完成部分，不生成伪完整报告。

## 11. 测试

必须覆盖：

- 三类助手都使用同一助手、消息和引用模型。
- 销售草稿中的价格、交付和功能承诺必须有当前引用。
- 客户项目 ACL 不被通用销售助手绕过。
- 项目待办不经用户确认不会写入。
- 项目归档后助手只读。
- 数据分析拒绝任意 SQL、Python 和未知工具。
- 多表单位、日期和去重键冲突要求确认。
- 图表不能指定任意文件路径。
- 工资、考勤生产开关默认关闭。
- 管理员无 HR 能力时无法绕过开关和权限。
- 外部模型不可用时确定性结果仍可追溯。
- 助手失败不会污染其他助手对话和状态。

## 12. 完成标准

- 用户在同一 RAGv3 中切换三类助手。
- 销售和项目输出是可追溯草稿，不会自动产生外部承诺或任务。
- Excel/CSV 计算结果可重放并引用具体数据范围。
- 普通表格分析不因工资、考勤审批未完成而被阻塞。
- 新助手没有复制用户、知识库、权限、聊天、收藏或审计系统。
