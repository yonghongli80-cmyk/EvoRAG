# RAGv3 回答可靠性设计

## 1. 目标

本阶段让系统能够区分“有充分依据”“依据有限”“资料冲突”和“无法回答”，并为跨文档比较与 Excel/CSV 精确问答建立统一证据模型。

可靠性不是让模型更自信，而是限制模型只能在可见、有效、可追溯的证据范围内回答。

## 2. 范围

包含：

- 无答案和证据不足处理。
- 高／中／低三级置信度及可解释理由。
- 同主题资料冲突检测。
- 跨文档比较。
- Excel/CSV 结构化数据保留和确定性计算。
- 可靠性结果与知识运营待办联动。

不包含：

- 联网搜索补充企业答案。
- 法律意义上的结论保证。
- 用一个精确百分比表示回答正确概率。
- 员工自助查询工资或考勤。
- 真实工资、考勤数据启用。
- 用 LlamaIndex 替换现有权限、Qdrant、版本和引用系统。

## 3. 统一证据模型

所有回答模式先产生 `EvidenceBundle`：

```text
EvidenceBundle
  question
  query_mode
  current_evidence[]
  historical_evidence[]
  structured_results[]
  conflicts[]
  retrieval_metrics
  permission_scope_fingerprint
```

每条文本证据必须包含：

- 逻辑文档 ID。
- 文档版本 ID 和版本号。
- 知识库 ID。
- 章节和分块。
- 当前／历史状态。
- 有效状态和更新时间。
- 检索分数和重排位置。

每条结构化结果必须包含：

- 数据集和文件版本。
- 工作簿、工作表。
- 使用列和数据类型。
- 过滤条件。
- 参与计算的行数。
- 单元格或行号范围。
- 运算类型和最终数值。

外部 API 不返回物理路径、原始 SQL、向量 ID 或无权限候选数量。

### 3.1 检索分数与版本状态来源

回答可靠性不得用排名、固定常量或归一化后的 RRF 值伪装成 reranker 相关度。现有检索链改为保留两个不同语义的分数：

- `retrieval_score`：RRF 融合分数，只用于排序和诊断，不与回答阈值比较。
- `rerank_score`：reranker 返回的原始 `relevance_score`，是 `reliability_min_score` 的唯一比较对象。

reranker 熔断、超时或返回无效分数时，`rerank_score` 为 `None`。系统保留证据和 RRF 顺序用于可解释降级，但不得生成一个替代分数。`EvidenceRef.score` 因此允许为 `None`，并携带 `score_source = reranker | unavailable`；有分数时来源必须是 `reranker`，无分数时来源必须是 `unavailable`。

当前/历史状态不得信任 Qdrant 的 `is_current`。证据构建只接受 SQLite `document_permissions.current_version_id` 选出的当前版本，以及由同一 SQLite 版本查询得到的历史回退；Qdrant 标志只参与修复与诊断。

若 SQLite ACL 查询没有得到任何可见当前或历史版本 ID，版本化检索必须直接返回空集，不能退回无版本限制检索。外部 reranker 只能接收已经按可见版本 ID 缩小过的 chunk；pipeline 中后置 ACL 过滤保留为纵深防御，但不能作为阻止不可见文本进入 reranker 的第一道边界。

## 4. 无答案决策

回答生成前执行 `AnswerabilityGate`。以下任一条件成立时不得生成普通肯定答案：

- ACL 过滤后没有当前有效证据。
- 最高相关证据低于可配置阈值。
- 只有历史或已确认过期资料。
- 用户要求精确数字，但只有非结构化近似描述。
- 关键结论存在未解决冲突。
- 表格查询字段、单位或时间范围不明确。
- 比较任务只有一侧取得证据。

结果类型：

- `answerable`：允许正常回答。
- `answerable_with_warning`：允许回答，但必须显示历史、范围或冲突警告。
- `clarification_required`：要求用户补充时间、部门、文件或统计口径。
- `insufficient_evidence`：明确说明现有资料无法确认。
- `permission_limited`：仅说明当前可访问资料不足，不透露是否存在无权限文件。

拒答仍保存问题、已使用证据和原因；高频无答案按归一化问题聚合后进入知识运营，不为每次失败单独建任务。

### 4.1 所有回答路径的统一边界

企业知识库请求按固定顺序执行：输入防护 → 用户/知识库范围确认 → 当前及历史检索 → ACL 过滤 → rerank → 文档注入过滤 → `EvidenceBundle` → `AnswerabilityGate` → 生成或固定拒答。证据计数、最高分、冲突和置信度只能读取 ACL 过滤后的证据。

同步回答、流式回答、再生成及 API 引用复用同一个已决策结果。拒答和澄清使用后端固定文案，不调用最终答案生成器，也不调用 `agent.run()`；流式接口只发送固定 token、空或可见引用及完成事件。

现有 `RAGAgent` 尚不能返回与最终答案逐项绑定的类型化证据，因此在该契约完成前，企业知识库中的 legacy agent 路径默认返回 `clarification_required`，不能绕过可靠性边界。表格等确定性工具以后通过 `structured_results` 进入同一边界，而不是恢复无引用 agent 答案。

企业知识库路径缺少 `user` 或 `user_db` 时返回 `permission_limited`，且不得先检索或调用模型。直接传入单个本地文件、未指定 `kb_id` 且未连接企业 `UserDB` 的 CLI 模式视为显式可信本地兼容模式；它不产生企业可靠性字段，也不得由 FastAPI 企业端点启用。

## 5. 置信度

UI 只显示高、中、低，不显示百分比。

评估输入：

- 当前有效引用数量。
- 最高和平均重排分数。
- 是否存在一手制度或负责人确认资料。
- 多个独立文档是否一致。
- 是否使用历史资料。
- 是否存在冲突。
- 结构化计算是否成功并可重放。

规则：

- 高：至少一条当前有效直接证据，结论没有冲突，精确数值来自确定性计算。
- 中：证据相关但不完整、只有单一来源、范围存在限制或需要轻度推断。
- 低：只有历史资料、证据覆盖不足或存在可披露的未解决冲突。
- `insufficient_evidence` 不显示低置信度答案，而显示“无法确认”。

响应同时返回 `confidence_reasons`，例如“引用 2 份当前制度”“统计来自 2026-06 考勤表 386 行”“发现两份制度生效日期不一致”。

## 6. 冲突检测

### 6.1 候选产生

冲突检测只在同一用户的可见证据中进行。先按主题、实体、适用范围和时间聚合候选，再让结构化抽取器提取：

- 主体。
- 属性。
- 值。
- 单位。
- 适用条件。
- 生效日期。
- 来源引用。

### 6.2 判定

确定性规则优先：

- 同一主体、属性、单位和适用范围下值不同。
- 同一流程有互斥步骤。
- 多份资料都标记当前有效但生效日期或适用部门重叠。

模型只能提出候选冲突，不能直接把文档标记为过期。负责人在知识运营台确认后，才改变有效状态或关闭冲突。

### 6.3 展示

冲突卡片并列显示两侧原文、文件、版本、章节、生效日期和适用范围。没有权限的一侧不参与检测，也不显示“可能还有其他资料”。

## 7. 跨文档比较

### 7.1 采用方式

引入 LlamaIndex Workflow 作为受限的比较编排器：

1. 识别比较维度。
2. 通过现有 ACL 检索选择候选逻辑文档。
3. 为每个文档生成子问题。
4. 并行调用 RAGv3 文档查询工具。
5. 汇总共同点、差异、适用范围和更新时间。
6. 校验每个单元格是否至少有一个引用。

LlamaIndex 不直接连接文件目录、SQLite 或 Qdrant；它只接收工具契约和经过权限过滤的响应。

### 7.2 输出

比较结果固定为：

- 比较对象。
- 比较维度。
- 对象 A。
- 对象 B。
- 差异说明。
- 适用范围。
- 引用。
- 证据状态。

任一比较项缺少一侧证据时显示“资料不足”，不得用常识补齐。比较最多默认选择 5 个文档；更多文档要求用户缩小范围。

### 7.3 多 Agent 边界

默认是一个 Workflow 编排器和多个无状态文档查询工具，不为每个文档维持常驻 Agent。只有复杂报告可以启用规划、取证、校验三个受控角色；它们共享不可变的权限上下文。

## 8. Excel/CSV 结构化能力

完整存储、查看器、切片、向量写入、问询、版本和迁移规范见：

`docs/superpowers/specs/2026-07-27-spreadsheet-knowledge-design.md`

本节只规定回答可靠性与表格能力的接口边界；详细规格优先。

### 8.1 双通道索引

Excel/CSV 同时进入：

- 文本检索通道：工作表说明、表头和行摘要，用于发现相关数据集。
- 结构化通道：保留原始单元格语义，用于精确筛选和计算。

不得只把整行拼成文本后依靠向量模型计算工资、出勤或统计结果。

### 8.2 元数据

新增逻辑实体：

- `structured_datasets`：绑定逻辑文档和当前版本。
- `structured_sheets`：工作表名称、行列范围、表头行。
- `structured_columns`：规范列名、原始列名、类型、单位、敏感标签。
- `structured_query_runs`：查询意图、验证结果、使用字段、过滤条件、行数和耗时。

文件覆盖产生新文档版本时，结构化数据生成新数据集版本；旧数据集只允许按历史引用访问，不能与当前数据静默混算。

### 8.3 查询网关

模型只允许生成结构化意图：

```json
{
  "dataset_id": 12,
  "operation": "aggregate",
  "metrics": [{"column": "迟到分钟", "function": "sum"}],
  "dimensions": ["部门"],
  "filters": [
    {"column": "日期", "operator": "between", "value": ["2026-06-01", "2026-06-30"]}
  ],
  "limit": 100
}
```

服务端完成：

- 数据集访问检查。
- 操作、列、函数和运算符白名单。
- 类型和单位验证。
- 最大扫描行数、返回行数和执行时间限制。
- 参数化 SQL 生成。
- SQLite `query_only` 执行。
- 结果最小化和引用生成。

禁止模型提交原始 SQL、Python 或 Pandas 表达式。现有通用 `sql_query` 不用于工资、考勤数据。

### 8.4 工资和考勤

第一版代码可以支持这类数据，但：

- 只使用虚构测试数据。
- 生产功能默认关闭。
- 只允许未来的 `hr_data_analyst` 能力访问。
- 系统管理员不因管理员身份自动获得明文读取权。
- 没有内网模型时，敏感明细由后端固定模板输出。
- 是否允许脱敏聚合结果进入外部模型，等待主管确认后配置。

## 9. API 与 UI

新增模式：

- 普通问答自动执行 AnswerabilityGate。
- 聊天输入区提供“比较文档”入口。
- 文件选择器只列出当前用户可见文档。
- Excel/CSV 问答显示“使用了结构化计算”标识。

建议 API：

- `POST /reliability/compare`
- `POST /structured-data/query`
- `GET /structured-data/datasets`
- `GET /answers/{message_id}/reliability`
- `PUT /knowledge-operations/conflicts/{conflict_id}/resolve`

响应中的比较、冲突和计算引用继续使用可信知识闭环的 citation 模型。

## 10. 失败与降级

- LlamaIndex Workflow 超时：返回已完成的逐文档证据，不生成完整比较。
- reranker 超时、熔断或返回非法分数：保留 RRF 排序供诊断，`rerank_score=None`，当前证据不能通过分数阈值。
- 企业知识库请求缺少用户或权限数据库：固定返回 `permission_limited`，不执行检索、最终生成或 agent。
- ACL 后没有任何可见版本：检索返回空集，不把未过滤 chunk 发送给外部 reranker。
- legacy agent 无类型化证据契约：固定返回 `clarification_required`，不调用 `agent.run()`。
- 一份文档解析失败：标记对应对象失败，其他结果可继续展示。
- 结构化类型推断失败：要求负责人确认表头和类型，不退化为猜测数值。
- 查询超限：提示缩小时间、部门或字段范围。
- 外部模型不可用：确定性计算仍可返回模板化结果。
- 置信度服务异常：回答标记“可靠性尚未评估”，不能默认显示高。

## 11. 测试

必须覆盖：

- 没有可见证据时拒答。
- 无权限候选不影响置信度和冲突提示。
- 历史资料只产生警告答案。
- 比较每个结论都有正确版本引用。
- 一侧缺证据时不补猜。
- 相同事实不同单位不会误判，规范化后不同值会判冲突。
- Excel 多工作表、空行、合并表头、日期和公式缓存。
- CSV 编码和分隔符异常。
- 结构化查询拒绝原始 SQL、越权列、超限和写操作。
- 计算结果能重放并定位单元格范围。
- 工资、考勤开关默认关闭。
- 管理员没有 `hr_data_analyst` 时不能查询明文。

## 12. 完成标准

- 无证据问题不再生成貌似确定的回答。
- 可靠性阈值只读取真实 reranker 分数；reranker 降级时不存在伪分数。
- 同步、流式、再生成与 legacy agent 入口都不能绕过同一决策边界。
- 置信度理由可由测试稳定复现。
- 跨文档比较任何结论都能追溯到具体版本和章节。
- Excel/CSV 数值由确定性工具计算而非语言模型心算。
- LlamaIndex 无法绕过现有 ACL 或直接读取底层存储。
