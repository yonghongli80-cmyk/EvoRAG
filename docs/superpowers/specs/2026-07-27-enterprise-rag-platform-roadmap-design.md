# RAGv3 企业知识平台后续路线设计

## 1. 文档目的

本文定义可信知识闭环完成后的产品路线、阶段依赖和统一平台边界。它是后续五个子项目规格的索引，不直接代替任何一期的详细设计和实施计划。

## 2. 已有前置条件

所有后续阶段都以以下文档完成并稳定为前提：

- `docs/superpowers/specs/2026-07-27-trusted-knowledge-loop-design.md`
- `docs/superpowers/plans/2026-07-27-trusted-knowledge-loop.md`

前置能力包括实名用户、逻辑文档权限、上传人负责人、不可变版本、当前有效版、可追溯引用、纠错反馈、负责人待办和知识运营页面。

如果前置实施尚未完成，后续工作只允许编写规格和测试夹具，不得绕开它另建第二套文档、权限、引用或任务模型。

## 3. 单平台原则

后续功能始终属于同一个 RAGv3：

- 一套 Vue 前端。
- 一套 FastAPI 后端。
- 一个登录身份和权限判断入口。
- 一套逻辑文档、版本、引用和知识运营数据。
- 一个 Qdrant 检索基础设施。
- 一个统一的聊天记录、收藏、通知和审计体系。
- 一个部署单元；不为每个场景启动独立服务、端口或数据库。

入职、制度、销售、项目和数据分析是同一聊天工作区中的“助手配置”，不是五个软件。助手只能缩小可访问范围或启用特定工具，不能扩大用户原有权限。

## 4. 总体架构

```text
Vue 单一工作台
  ├─ 搜索与普通问答
  ├─ 知识运营
  ├─ 个人首页
  └─ 场景助手选择器
          │
FastAPI 统一 API
  ├─ 身份、ACL 与能力权限
  ├─ 文档、版本、引用与反馈
  ├─ 检索可靠性服务
  ├─ 结构化数据查询网关
  ├─ 助手配置与 Workflow
  ├─ 收藏、订阅、通知与历史
  └─ 审计、备份与交接
          │
SQLite + Qdrant + 不可变版本文件
```

LlamaIndex 不替换现有存储和权限系统。它只在跨文档比较等复杂任务中，通过适配器承担问题拆解、工具路由和结果合成。所有实际取数仍调用 RAGv3 的权限安全服务。

## 5. 分期顺序

### 阶段 0：可信知识闭环

实施现有设计与计划。没有稳定的负责人、版本和引用，后续置信度、冲突检测、收藏更新提醒和场景助手都没有可信依据。

### 阶段 1：回答可靠性

规格：`2026-07-27-answer-reliability-design.md`

交付：

- 无答案和证据不足处理。
- 高／中／低置信度及理由。
- 冲突资料检测。
- LlamaIndex 跨文档比较 Workflow。
- Excel/CSV 结构化导入与确定性查询。

### 阶段 2：企业治理

规格：`2026-07-27-enterprise-governance-design.md`

交付：

- 职责分离和能力权限。
- 敏感文件分级。
- 不可抵赖审计。
- 批量权限。
- 加密备份和恢复演练。
- 离职账号停用与资产交接。

工资、考勤真实数据必须经过主管确认后才允许启用；系统管理员默认没有明文查看权。

### 阶段 3：员工体验

规格：`2026-07-27-employee-experience-design.md`

交付：

- 搜索建议。
- 推荐问题和匿名常问问题。
- 收藏。
- 更新订阅与站内通知。
- 可检索个人历史。
- 首页快捷入口。

### 阶段 4：助手平台、入职与制度

规格：`2026-07-27-assistant-platform-design.md`

交付统一助手配置与 Workflow 运行时，首批启用入职助手和制度助手。

### 阶段 5：销售、项目与数据分析助手

规格：`2026-07-27-advanced-assistants-design.md`

复用阶段 1 的可靠性和表格查询、阶段 2 的治理以及阶段 4 的助手运行时，不创建新平台。

## 6. 阶段门槛

每一期必须独立完成：

1. 规格确认。
2. TDD 实施计划。
3. 数据迁移和回滚说明。
4. 后端权限与失败路径测试。
5. 前端角色、空状态和错误状态测试。
6. 全量回归和构建。
7. 开发日志和运维文档。

下一期只能在上一期回归通过、迁移可重复执行且工作区干净后开始。

## 7. 统一技术决策

### 7.1 编排

- 普通问答使用当前 RAG pipeline。
- 明确步骤的业务使用确定性 Workflow。
- 跨文档比较使用受控 LlamaIndex Workflow。
- 多 Agent 只用于复杂比较或报告，默认关闭自主循环。
- 权限检查、SQL 校验、文件操作和状态变更永远是确定性服务，不由 Agent 决定。

### 7.2 外部模型

当前 DeepSeek／百炼接口视为外部模型服务。

- 普通知识按现有企业决策使用。
- 工资、考勤真实明细在主管确认前禁止启用。
- 结构化查询工具在本机执行不代表结果没有发给外部模型。
- 没有内网模型时，敏感查询结果使用后端模板输出；允许发送的脱敏聚合结果由策略配置决定。

### 7.3 数据来源

本路线继续使用上传适配器。NAS、SMB、WebDAV 和钉钉连接器继续作为独立后续规格，不混入这五期。

## 8. 明确不做

- 不拆分为微服务或五个独立产品。
- 不引入第二套用户、文档权限或聊天历史。
- 不允许 Agent 自主授权、批量下载或执行任意 SQL。
- 不把置信度伪装成数学准确率。
- 不在主管确认前用真实工资、考勤数据验证原型。
- 不在本路线内实现 NAS 或组织上下级继承。

## 9. 成功标准

- 员工能在一个入口完成问答、比较、收藏、订阅和场景工作。
- 无证据时系统选择拒答而不是编造。
- 每项比较结论和表格数值都能追溯到文档版本或单元格范围。
- 管理职责不自动获得业务明文读取权。
- 权限撤销后，历史、收藏、通知和助手都不能继续泄露内容。
- 新助手只增加配置和 Workflow，不复制账号、权限、检索或数据存储。
