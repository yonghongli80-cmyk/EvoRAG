# 真实模型 P99 隔离基线验收

用户已授权继续计划、使用 Luna 子代理，并选择先采集低并发基线；后续补充模型费用无上限，效果不好则优化。本轮不设未经确认的 P99 SLO，也不操作原8080服务、业务数据或部署。

## 运行方式与边界
- 基线源码为 main a448d25，复用现有干净 managed worktree，新分支 codex/real-model-p99-2026-10-24；实际服务在本轮 git archive 源码副本中启动，使用完整真实 FastAPI /query、鉴权、RAG、embedding、rerank、Jev、生成调用链。
- 副本不含 .env、业务数据、旧向量目录或记录。只选择性将现有模型及检索配置在内存注入该子进程；不复制业务认证/数据/演化配置，不把凭据放命令行、报告或源码。
- 新建合成语料、临时账号、SQLite/Qdrant/上传/版本/结构化目录及本轮日志；正常 lifespan 在这份独立副本上执行。显式禁用演化、候选、materials worker、备份、共享Redis；不使用真实问题或文档。
- 已核对模型端点均为远程HTTPS；保持实际配置的 Jev active/三轮投票、模型、温度及检索参数。共享供应商配额仍存在，只进行受限基线，不做饱和容量测试。

## 工作负载与证据
先6条串行质量/链路试跑与2条预热；满足真实生成、引用、关键事实正确后，最多200条同步 /query 测量，并发上限2、总启动速率不超过12请求/分钟。遇429/认证/计费/预算错误立即停止新请求；连续2次不健康或新业务PID改变/就绪失败即停止；单次完整请求超时120秒。所有未完成/失败请求保留，不能用删失败样本美化分位数。

每个请求保留ID、合成case、开始/结束/耗时、HTTP状态、成功/关键事实/来源校验、答案摘要哈希及字符数；不保留真实密钥或供应商原始响应正文。真实外呼旁路记录仅保存操作类别、状态、响应模型/usage/请求ID哈希及耗时，原始SDK/网络调用不得被替身替换。

试跑阶段事实/来源检查失败仍拒绝后续测量。正式测量阶段的自动事实检查失败保留原始失败标记和有界合成答案，标为待复核，继续受限采样以观察错误率；HTTP/网络失败、缺失相关来源、鉴权/计费/限流或服务健康异常仍停止。结束后逐条复核异常，不删除失败行，不将真正错误重标成功；格式假阴性及其修正单独留档。

报告 nearest-rank P50/P95/P99、max、错误率、成功/所有终态样本数、QPS、各逻辑route及preparation/rerank/generation/Jev阶段覆盖；明确200样本尾部仍稀疏，不宣称稳定SLO。混合接口旧P99/离线烟测不可横比。供应商usage是响应元数据，不冒充独立账单审计。

## 判定与优化
基线完成条件为可审计原始样本、真实外呼证据、限定负载范围、质量与失败如实记录、业务服务存活及本轮资源清理。不因未定义阈值宣布性能通过。
若试跑失败/错误率非零/质量明显不达标，先查根因再做最小修复；若尾延迟突出，定位耗时段和有效优化，保留默认生产行为与安全门禁，以同一case、模型、并发/速率、缓存口径作前后对照。配置实验仅在隔离实例生效。涉及业务语义取舍/更换模型的选择单列，不默默改生产。
