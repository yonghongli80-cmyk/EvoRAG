# 深度审查后的增量缺陷整改

## 目标与授权

用户要求深入探查现有项目、修复发现的 bug，先写计划，再并行启动 Luna 执行；主代理统筹验证和集成。沿用“不影响现有服务和业务数据”“别改坏了”的约束，不再要求一次执行方式确认。基线为 `c60745d`，使用已附加的隔离工作树和新分支 `codex/deep-audit-remediation-2026-10-24`。

## 证据与问题

三路 Luna 分别追踪后端状态/权限、前端/API 契约、运行/部署；主代理补查查询、缓存和模型流生命周期。

| 编号 | 触发与当前问题 | 本轮要求 |
| --- | --- | --- |
| A1 | 陈旧 task CAS 返回冲突，版本 validity 却已独立提交为过期；临时 SQLite 已复现 | 任务状态、版本 validity、事件同事务提交/回滚 |
| A2 | KB-A 迟到详情响应覆盖 KB-B；确认框打开后切库也可能把当前 route 与旧文档拼接 | 页面及异步操作始终绑定发起时的 KB；失效响应不写状态或导航 |
| A3 | `/files` 的全局 `in_kb` 被当作目标 KB 关联状态 | 已在其他 KB 的文件仍可加入当前 KB；当前库已有文件继续排除 |
| A4 | legacy 与 pool 的生成器 aclose 后底层 OpenAI HTTP 响应仍未关闭；真实 SDK + MockTransport 已复现 | 正常结束、提前关闭、取消、失败及重试均及时释放所属流；完整链路取消可传递 |
| A5 | regenerate 创建 AbortController 却未把 signal 传给 Axios | “停止”取消浏览器请求，迟到结果不覆盖当前 UI；不声称可撤销服务器已提交写入 |
| A6 | KB 删除仅清当前路径，删除权限行级联抹掉历史路径记录 | 删除当前与历史版本文件，路径受根目录约束；失败保留可重试身份 |
| A7 | upload/link 的 overwrite ingest 失败删除已存在的 `kb_documents` 行；稳定重复reject没有复现此问题 | 只清理由当前调用新建的 pending 行，失败不破坏既有目录记录；reject保留作正向控制 |
| A8 | Redis 成功日志直接输出带认证信息的 URL | 日志只记连接状态；不改变连接参数 |
| A9 | 部署在 pull 前校验端口，实际 build/up 用 pull 后配置 | 绑定提示检查更新后的文件，保持现有告警策略 |
| A10 | 备份到期判断在跨进程创建锁外，允许同周期重复决策 | 在同一备份锁协议内检查到期并创建，显式手工备份锁语义不变 |
| A11 | `if ! main` 使 Bash 的 errexit 在函数链被抑制；离线 stub 证明 pull/备份失败后仍进入 up 并退出0 | 部署各前置阶段显式传播失败；up失败不能被后续ps成功掩盖 |

A1/A4 已有实际离线复现；A7 的覆盖失败由内部ASGI+临时SQLite复现，默认reject假设已被反证收窄。其余必须先用有意义的失败回归确认，不凭静态报告宣布已修。

调查期间一次子代理脚本误进app lifespan，遍历了C隔离树的上传目录并发出使用conftest假密钥的embedding请求，均401；该进程已Ctrl-C退出1，不能把这个尝试称为离线。其可能产生的隔离树启动副作用无法由缺失的事前文件快照完全排除，未据此声称零写入。原D业务服务未参与，事后核对PID48512/启动时间/ready200/.env哈希均保持。后续pytest统一加载本轮忽略目录中的offline_network_guard，禁止外部TCP与8080连接；不再运行该旧probe。

## 方案与范围

采用现有框架内的最小修复，按不重叠文件分组并行，主代理串行审阅、提交和集成。另一方案是同时重做持久层/多副本生命周期协议，会引入数据迁移和运行切换，当前不采用。单纯增加测试或改变断言不能修复已复现的业务副作用，也不采用。

KB 删除与并发上传的跨存储协调需要单独设计持久化准入/恢复协议；本轮报告保留该风险与确定性复现步骤，不以一个进程内锁宣称解决多进程一致性。默认 Compose 整栈健康依赖与本地可选组件的关系、普通资源 403 的全会话 reset 均记录为现有拓扑/交互契约待办，未获得足够证据前不改变它们。历史版本内容实际回收与元数据保留顺序则在本轮修复。

## 全局约束

- 不重启、停止、部署或压测现有 `127.0.0.1:8080` / PID48512；不读写业务数据库、业务向量目录或真实候选，不复制或输出 `.env`。
- 单元/API 测试必须加载 `tests/conftest.py`，所有临时数据库/文件位于系统 Temp；不把 `--basetemp` 指到仓库。离线供应商替身不得发送真实网络请求。
- 使用既有隔离 Python 锁环境；前端仅使用独立 Node22/frontend-copy，不修改指向原工作区的 node_modules junction。
- 保持现有 ACL、admin/legacy KB 行为、状态机、canary shadow、沙箱 fail-closed；api.py 不超过830行，pipeline.py 不超过1000行，不放宽架构门禁。
- 不升级依赖、不改模型默认、不重复真实模型基线或 Docker 运行验收。已完成的历史事项不重新计入成果。
- 子代理只修改任务白名单文件，不执行 Git 写操作或开启下一层子代理；主代理统一提交。可并行的前提是文件与测试资源互不冲突。

## 验收与边界

每个代码任务保留 RED/GREEN 输出及定向回归，之后在稳定源码上执行一次完整后端、前端测试、类型/构建与 lint/架构检查；修复失败时保留原失败结果并追根处理。fresh Luna 按规格和代码质量复查，最终做整分支审查。交接必须区分已修 bug、待设计问题、缺少外部条件的验收，不声称整个项目无 bug 或已在现有业务实例上线。
