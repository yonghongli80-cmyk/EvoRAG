# 鉴权与全项目审查问题收口设计

日期：2026-08-21  
状态：已完成

## 目标

在不改变文件页面既有 private/shared/public 三级权限、不中断当前真实服务、也不误删真实业务数据的前提下，逐项修复本轮自审查发现的鉴权、知识库授权、SQLite 事务、测试隔离、前端能力展示和持续集成问题。

## 核心设计

1. 所有用户态接口统一通过 `resolve_principal` 校验用户存在、账号启用状态、组织人员启用状态和 `security_version`。旧的 `verify_api_key` 只保留 API Key 兼容能力，不再形成较弱的 JWT 校验旁路。
2. 组织模式关闭匿名注册。登录页使用账号编号或姓名输入，不再匿名公开完整员工目录。登录失败按账号与来源进行限流，并记录不含密码的审计事件。
3. 浏览器会话改为 HttpOnly、SameSite Cookie；前端不再把 JWT 写入 localStorage。非浏览器 API Key 与显式 Bearer Token 继续兼容。状态变更请求增加同源校验，退出登录清除 Cookie。
4. 初始密码仍为 `123456` 且不强制修改；但绑定到非回环地址时，如果仍存在启用且使用初始密码的组织账号，则拒绝不安全启动并给出操作提示。
5. 知识库只允许有效组织成员按组织角色创建和访问，不再回退到个人 owner/scope 模型；文件页面继续使用原有三级权限。
6. 标签只统计调用者可访问的文件；知识缺口分析仅允许管理员查看。所有资源权限失败均 fail closed。
7. 重复知识库元数据写入使用幂等 SQL 或明确回滚；组织人员 PATCH 中未提供的兼职部门必须保持原值。
8. 前端严格按 `read/manage/administer` 展示能力：删除知识库只允许 `administer`，内容维护允许 `manage`。
9. 测试默认替换真实 UserDB、上传目录和向量存储，任何测试都不得写入 `data/` 或连接正在运行的本地 Qdrant。
10. CI 必须执行后端测试、前端测试、前端生产构建、npm audit 和 Python 依赖审计。

## 数据清理

真实库清理分为四步：创建权威备份并校验、生成只读候选报告、根据稳定测试前缀和引用关系精确确认、在一个事务内删除。名称含糊或不能证明来源的数据一律保留。清理命令同时提供 `--dry-run` 和 `--apply`，应用前再次核对备份。

## TDD 与验收

每个问题必须先加入能够复现当前缺陷的失败测试，确认红灯后才写最小修复。相关测试通过后再重构。最终验收包括后端全量测试、前端全量测试、生产构建、Ruff、npm audit、pip-audit、Git 差异检查和本地服务健康检查。

## 非目标

- 不接入 SSO、LDAP、企业微信或钉钉。
- 不改变固定虚构组织、账号编号或初始密码规则。
- 不把文件页面改造成组织权限。
- 不自动删除来源不明确的真实数据库记录。
