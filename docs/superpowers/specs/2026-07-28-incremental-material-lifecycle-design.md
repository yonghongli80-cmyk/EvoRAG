# RAGv3 增量资料生命周期与智能整理设计

## 1. 目标

在现有“逻辑文档 + 不可变版本 + ACL”基础上，支持约 300 名员工日常频繁新增、替换、删除和整理资料，而不靠全量重建知识库。系统必须只处理真实变化的内容、让已删除资料立即停止被检索和下载、在保留期内可恢复，并让员工通过文字指令预览并确认资料整理操作。

本设计覆盖现代及旧版 Office、普通文档、扫描 PDF、图片存档和受控压缩包。Git 代码仓库、NAS 自动同步、语音输入和多模态图像理解均不在本阶段范围内。

## 2. 成功标准

- 内容未变的重复上传不触发解析、嵌入或新版本。
- 文件替换只重新处理变动的文本/表格块；同内容块复用嵌入缓存，但新版仍有独立版本引用。
- 删除后，普通用户在下一次查询、打开和下载时立即不可见；管理员可在 30 天内恢复。
- 回收期到期后，原文件、派生缩略图、OCR 文本、结构化文件和向量由后台分批清理。
- 用户询问“我的入职资料在哪里”时，系统只在该用户当前可见的资料中定位，并返回逻辑位置与授权下载入口。
- 用户的文字整理指令只生成预览；确认后才改变逻辑目录、标签和资料类型，且可审计、幂等、可撤销。
- 上传、批量导入、文件夹索引、预览和解析统一使用同一格式能力注册表，不再维护相互矛盾的扩展名列表。
- 压缩包先完成安全检查并展示内容清单；上传人确认后，受支持的内部文件才成为可检索子资料。

## 3. 范围与非范围

### 3.1 包含

- 高频新增、替换、删除、恢复和到期清理。
- 版本差分、嵌入缓存、任务去重、防抖、失败重试和后台回收。
- 文档名称、逻辑位置、标签、资料类型、上传人、负责人、时间和 OCR 文本的权限过滤检索。
- 扫描 PDF 的本地 OCR；图片的原图版本、缩略图和元数据存档。
- `.pptx` 页级抽取，`.doc/.xls/.ppt` 旧版 Office 的隔离转换，以及 `.zip/.rar/.7z` 的安全清单与确认后导入。
- 文字指令生成资料归类/打标/逻辑移动预览，确认后的批量执行与撤销。

### 3.2 不包含

- Git 仓库、提交差分、代码符号检索或代码向量化。
- NAS、SMB、WebDAV 或钉钉自动同步。
- 麦克风语音转写。
- 多模态模型、图像向量、图像问答或临时把图片发送给模型阅读。
- 把手写签名、手写姓名或图片人脸用于身份确认、权限判断或自动归属。
- 未经后续治理审批的工资、考勤等受限资料生产启用。

### 3.3 格式能力分级

系统不得用“后缀在列表中”代表格式已经完整支持。每种格式在统一 `FormatCapabilityRegistry` 中分别声明：签名/MIME、允许后缀、存档、预览、正文抽取、OCR、结构化查询、语义索引和压缩容器能力。上传接口、批量导入、文件夹索引和后台任务只能查询该注册表。

第一阶段能力矩阵如下：

| 格式 | 存档 | 预览 | 内容处理 | 检索/引用 |
|---|---:|---:|---|---|
| `.txt/.md` | 是 | 是 | 编码检测后提取文本 | 段落级 |
| `.pdf` | 是 | 是 | 文本层优先；扫描页本地 OCR | 页码/区域 |
| `.docx` | 是 | 是 | 段落、标题、表格 | 章节/段落 |
| `.xlsx/.csv` | 是 | 是 | 进入表格专用结构化管道 | 工作表/单元格范围 |
| `.pptx` | 是 | 是 | 页标题、正文、备注、表格；不理解页内图片 | 幻灯片页码 |
| `.doc/.ppt` | 是 | 转换成功后 | 隔离转换为现代格式再抽取 | 原文件版本 + 转换后位置 |
| `.xls` | 是 | 转换成功后 | 非执行解析优先；必要时隔离转换后进入表格管道 | 工作表/单元格范围 |
| `.jpg/.jpeg/.png/.tif/.tiff/.bmp` | 是 | 缩略图 | 不做 OCR、视觉理解或图像向量 | 仅元数据 |
| `.zip/.rar/.7z` | 是 | 内容清单 | 确认后处理允许的内部文件 | 容器 + 子资料 |

扩展名、声明 MIME 和文件魔数必须相互兼容；不一致时进入 `format_mismatch` 隔离状态，不能仅通过改后缀绕过限制。宏启用格式、嵌入对象和外部链接永不执行。尚未安装所需解析/转换能力时，注册表必须报告 `archive_only` 或 `temporarily_unavailable`，不能假装已经索引。

### 3.4 旧版 Office 安全转换

原始 `.doc/.xls/.ppt` 永远作为不可变版本保存。解析器优先选择不会执行宏或公式的库；只有缺少可靠非执行解析时，才在无网络、只读输入、独立临时目录、CPU/内存/时限受控的转换进程中生成派生现代格式。转换器禁用宏、外部链接、嵌入对象执行和自动更新。

派生文件不是新的用户文档，不产生独立 ACL 或下载入口；它记录原版本 ID、转换器版本、解析器版本和内容哈希。转换失败时，原文件仍可按元数据定位和下载，状态明确显示“仅存档，正文未索引”。

### 3.5 压缩包清单与确认导入

`.zip/.rar/.7z` 本身是一个逻辑容器文档。上传后先流式保存原包并生成只含安全元数据的清单，不立即展开到正式资料区。清单规范化 Unicode 文件名和相对路径，并逐项显示格式、压缩大小、预计展开大小、是否支持和拒绝原因。

默认限制为：压缩包原文件不超过 200 MB、内部单文件不超过 50 MB、总展开大小不超过 1 GB、最多 1,000 项、最大嵌套深度 2、单项压缩比不超过 100:1。路径穿越、绝对路径、符号链接、设备文件、加密条目、递归包超限和危险可执行内容不得解压或索引。解包和旧版 Office 转换一样在无网络、资源受限的隔离进程中运行。

上传人确认清单后，受支持条目按清洗后的相对路径成为容器下的子逻辑文档，继承容器 ACL 且不能扩大权限。每个子资料具有独立逻辑文档 ID、版本、引用和下载动作；下载仍从原包安全流式提取或使用受控派生副本，不返回内部物理路径。

替换压缩包时，以“规范化相对路径 + 内容哈希”差分：相同条目不重建，新增条目创建子资料，变更条目创建新版本，删除条目随容器新版本进入回收状态。容器确认与子资料版本切换必须记录一个批次 ID；批次中途失败时，新子版本不可见，旧容器版本仍是当前版本。

## 4. 数据与生命周期

### 4.1 逻辑文档和版本

`document_permissions` 继续是逻辑文档、ACL 和稳定 URL 的主记录；`document_versions` 保存不可变版本。显示目录、显示文件名、标签和资料类型属于逻辑文档元数据，不使用服务器物理路径作为用户可见位置。

版本状态扩展为：

```text
staging -> indexing -> current -> historical -> recycle_pending -> purged
                     \-> failed
```

`current` 仅由 SQLite 的 `current_version_id` 决定。Qdrant 的 `is_current` 是派生修复状态，不能单独决定可见性。逻辑文档删除使用 `deleted_at`、`deleted_by` 和 `restore_until` 墓碑字段；删除不会马上物理删除数据。

### 4.2 替换、增量索引和去重

新文件先以流式方式写入隔离暂存区并计算文件内容哈希；HTTP 层不得把整个 Office 文件或压缩包一次性读入内存：

1. 哈希相同：返回 `unchanged`，不创建版本和任务。
2. 哈希不同：创建 `staging` 版本，提取文本、OCR 文本或表格结构。
3. 每个解析块以 `content_fingerprint = SHA-256(normalized_content + parser_schema_version)` 标识。
4. 新块和修改块取得/写入嵌入；相同指纹可复用受版本隔离保护的嵌入缓存。
5. 所有新版文件、解析结果和向量准备成功后，以一个 SQLite 事务切换 `current_version_id`。
6. 旧版本改为 `historical`，其向量与派生物保留到回收策略允许清理时；当前检索永远按 SQLite 解析出的当前版本 ID 过滤。

嵌入缓存只缓存向量数值和模型/维度/归一化版本，不缓存用户权限、来源路径或可直接展示的文件内容。新的 Qdrant point 仍必须携带新的 `document_version_id`、逻辑文档 ID 和 ACL 可过滤字段。

本阶段的 30 天回收仅适用于被删除的逻辑文档和资料整理批次，不自动清除正常替换产生的历史版本。历史版本继续遵守可信知识闭环的引用和回退规则；后续如需按年限、数量或法律保全状态清理历史版本，必须进入企业治理的独立保留策略。

### 4.3 索引任务

所有耗时操作进入持久化 `document_index_jobs`，而不是由 HTTP 请求同步完成。任务至少包含：逻辑文档 ID、目标版本 ID、操作类型、内容哈希、状态、尝试次数、可重试时间、去重键、创建/完成时间和最后一个安全错误码。

操作类型为 `index_version`、`reindex_metadata`、`tombstone_document`、`purge_version`、`purge_document` 和 `repair_vector_flags`。同一逻辑文档只允许一个活动的索引任务；连续替换在 5 分钟防抖窗口内折叠为最新版本。已失去当前资格的任务在运行前后均检查版本指针，过期任务安全取消，不得覆盖较新的版本。

初始容量策略为：解析/OCR 最多 2 个并发任务，嵌入最多 4 个并发任务，物理清理只在低峰期批量运行。队列超过配置上限时，上传仍可保存为 `staging`，接口返回“等待处理”而不是无限占用请求线程。

普通单文件默认上限统一为 50 MB；压缩包使用 3.5 节的独立限制。限额必须从配置读取并在上传前端显示，后端仍以实际接收字节和解包后的安全计数为准。

### 4.4 删除、恢复与回收

删除逻辑文档时，后端在一个事务中写入删除墓碑、递增受影响用户的权限版本、写入 `tombstone_document` 任务和审计事件。所有搜索、预览、下载、引用打开和通知投递都同步检查墓碑，因此删除提交后立即不可见。

恢复只允许删除者、负责人或管理员在 `restore_until` 前执行；恢复重新指向删除前的当前版本，并排入必要的索引修复任务。默认 `restore_until = deleted_at + 30 days`。

到期回收由 `purge_document` 任务完成：先验证仍为删除状态且恢复期已过，再删除版本文件、缩略图、OCR/解析派生物、结构化数据和对应向量，最后把版本记为 `purged`。任务按文档幂等执行；失败保留可重试状态，不删除数据库审计记录。被已提交回答引用的资料，保留最小引用审计记录和“资料已依保留策略清除”状态，不保留可下载正文。

## 5. 资料定位与安全下载

### 5.1 检索策略

资料定位不是只依赖向量。后端先用当前 ACL 和删除墓碑过滤候选资料，再组合：

- 精确过滤：员工姓名、工号、资料类型、标签、上传人、负责人、时间范围和逻辑目录；
- 全文检索：文件名、OCR 文本、抽取正文和资料描述；
- 语义检索：普通文档和 OCR 文字块，用于“入职时签过的保密资料”这类表述。

员工姓名和工号的归属判断优先使用明确字段和全文匹配，不以向量相似度或签名识别作为身份结论。低置信度提取只作为候选标签，必须经上传人/负责人确认后才成为正式资料归属。

### 5.2 扫描 PDF 和图片

扫描 PDF 通过本地 OCR 产生受版本绑定的文字层；OCR 文字可全文/语义检索，并在回答中标明“OCR 结果，可能有识别误差”。图片仅保存原图、缩略图、显示文件名、逻辑目录、标签、上传人和其他人工元数据。图片不做视觉模型调用、不做图像嵌入，也不根据图片或手写签名推断人物身份。

用户可见的结果只返回逻辑位置、显示名称、资料类型、更新时间、版本状态和授权动作。下载通过现有的版本下载接口；该接口每次请求重新执行 ACL 和删除状态检查，绝不返回物理路径或由模型拼接 URL。

## 6. 文字指令整理

### 6.1 指令和预览

用户可输入例如“把我今年上传的劳动合同和入职登记表放到我的人事资料/入职材料，其他图片标记为待整理”。模型只生成受限的 `OrganizationProposal`，包含：作用域、候选文件 ID、目标逻辑目录、待加/待删标签、待设资料类型、判断理由、置信度和无法执行原因。

模型只能引用后端预先 ACL 过滤后的元数据和允许的文本摘要。它不能产生文件系统路径、SQL、任意 API 调用、下载 URL 或未在候选集合中的文件 ID。

预览界面必须逐项展示“将修改什么”，并把低置信度、歧义目录、无权限文件和被删除文件标为不执行。预览在 15 分钟后过期。

### 6.2 确认、执行和撤销

用户确认时携带预览 ID、预览版本、确认范围和幂等键。后端重新执行 ACL、文件当前版本、删除状态、目录合法性和资料类型白名单检查；任何不再满足条件的项单独标为冲突，不能影响其余可执行项。

确认后的批量操作仅修改逻辑目录、标签、资料类型和显式归属候选，不物理移动文件、不修改历史版本、不改变 ACL。每一项写入前后元数据、操作者、时间、指令摘要、预览 ID 和幂等键的审计记录。每次确认生成 `organization_batch`；用户可在 30 天内撤销该批次，撤销只在对象元数据仍匹配该批次写入结果时恢复旧值，已被后续操作改变的字段返回冲突而不覆盖。

## 7. 安全、隐私和可观测性

- 所有上传、替换、删除、恢复、任务执行、整理确认和撤销均使用现有 ACL 与权限版本失效机制。
- 已删除资料、待分类敏感资料、无权资料和过期版本不能进入模型上下文、搜索候选或通知摘要。
- OCR 在本地受控执行；若 OCR 失败，原文件仍可按元数据定位，但不会以 OCR 文本参与检索。
- 审计日志不保存全文、OCR 全文、物理路径、访问令牌或模型原始提示词。
- 指标只记录队列深度、任务时长、成功/失败数、重试数、嵌入缓存命中率、回收字节数和组织预览/确认/撤销数量。

## 8. 验收场景

1. 同一文件重复上传，确认无新版本、无 OCR/嵌入任务。
2. 替换文档中一个段落，确认当前版本只检索新版，旧版本仍可审计，嵌入缓存命中未变段落。
3. 连续三次替换同一资料，确认只索引最后一个版本，较早任务不会回写当前指针。
4. 删除资料后，搜索、打开、下载、通知投递和模型资料定位均返回不可访问；30 天内恢复后重新可用。
5. 到期回收后，原文件、派生物和向量不存在，但审计与引用状态仍可追溯。
6. 扫描 PDF 的印刷姓名/资料类型可用于定位；手写签名不会产生自动归属。
7. 图片可按名称、目录、标签和上传人定位并安全下载，但不会因图片内容被模型检索。
8. 文字整理指令仅显示预览；确认后只改变允许的逻辑元数据；重复确认不重复执行；撤销不会覆盖后续人工修改。
9. `.pptx` 的文字和备注可被检索并引用到幻灯片页码，页内图片内容不会被模型理解。
10. `.doc/.xls/.ppt` 转换时不执行宏、公式更新、嵌入对象和外部链接；转换失败后原文件仍处于可下载的“仅存档”状态。
11. 压缩包在确认前没有可检索子资料；确认后只导入支持且通过安全检查的条目。
12. 路径穿越、压缩炸弹、超深嵌套、加密条目和伪造扩展名均被隔离，不留下可检索或可执行的派生文件。

## 9. 实施顺序

本功能依赖可信知识闭环完成其版本、ACL、版本下载和 SQLite 当前版本指针。建议在可信知识闭环完整验证后实施，并在回答可靠性、表格知识、治理、员工体验和助手平台计划之前作为一个独立计划执行。Git/NAS 来源适配器在该计划完成后另行设计。
