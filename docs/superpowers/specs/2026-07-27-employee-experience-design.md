# RAGv3 员工使用体验设计

## 1. 目标

本阶段让员工更快找到入口、继续未完成工作并获知知识变化，同时保证收藏、历史和推荐不会成为绕过当前权限的旁路。

## 2. 范围

包含：

- 搜索建议。
- 负责人推荐问题和匿名常问问题。
- 文件、引用、问题和助手收藏。
- 文件、知识库和负责人的更新订阅。
- 站内通知。
- 可检索的个人历史。
- 首页快捷入口。

不包含：

- 钉钉、邮件、短信通知。
- 基于工资、考勤或敏感问题的画像推荐。
- 公开奖励榜、员工搜索排行。
- 自动执行订阅内容中的业务操作。
- 新建第二套个人门户。

## 3. 首页

登录后仍进入同一 RAGv3 工作台。首页由可独立加载的区块组成：

- 继续上次对话。
- 最近访问文件。
- 我的收藏。
- 订阅更新。
- 常用助手。
- 待我处理。
- 推荐问题。

每个区块失败时独立显示错误和重试，不能导致整个首页不可用。用户可以隐藏和排序区块，第一版不做任意拖拽布局。

## 4. 搜索建议

### 4.1 来源

建议按以下优先级合并：

1. 当前输入与可见文件／知识库名称前缀匹配。
2. 负责人配置的推荐问题。
3. 用户自己的最近问题。
4. 当前权限范围内的匿名常问问题。
5. 用户收藏的文件和助手。

建议项包含类型、标题、所属知识库和动作，不返回正文片段。

### 4.2 权限

生成建议前重新计算当前用户可见资源。缓存键包含用户权限版本；分享撤销、账号停用或文件敏感等级变化时立即失效。

绝不通过“结果被隐藏”“还有 N 个结果”等方式泄露无权限资源数量。

### 4.3 交互

- 输入两字符后请求。
- 150–250ms 防抖。
- 键盘上下选择和 Enter 执行。
- 问题建议进入聊天。
- 文件建议打开文件详情。
- 助手建议切换当前助手配置。

## 5. 常用问题

分为两类：

### 5.1 推荐问题

文件负责人或知识库负责人维护问题、展示顺序和适用范围。问题本身不保存固定答案，点击后使用当前版本重新查询。

### 5.2 大家常问

系统按规范化问题聚合最近 30 天使用情况。只有达到可配置的最少不同用户数才展示，默认 5 人；显示大致热度，不显示提问人和精确次数。

聚合按知识库或助手范围分区，但分桶不是最终授权。快照保存支持该问题的资源 ID；返回前按当前用户可见资源集合和权限版本再次过滤，没有可见当前证据就隐藏。不能把全公司的问题文本放进一个公共热门池。

以下问题不参与公开聚合：

- 涉及严格受限数据。
- 被敏感检测命中。
- 用户明确标记为私密。
- 只有少数用户提出。
- 管理员或负责人手动排除。

## 6. 收藏

收藏对象：

- 逻辑文档。
- 回答引用。
- 问题。
- 场景助手。

收藏回答时不永久冻结答案。系统保存原问题、assistant message ID 和引用版本；打开时显示：

- 当时答案。
- 引用是否仍有效。
- 是否已有新版本。
- “使用当前资料重新回答”动作。

文件删除、权限撤销或敏感等级提高后，收藏记录可以保留标题为“已不可访问”，但不能显示旧摘要、引用正文或下载链接。

同一用户、对象类型和对象 ID 唯一；重复收藏幂等。

## 7. 订阅与通知

可订阅：

- 逻辑文档。
- 知识库。
- 文件负责人发布的更新。

触发事件：

- 当前版本更新。
- 文档被确认过期。
- 纠错任务处理完成。
- 负责人发布重要更新。
- 订阅资源被归档或移除。

第一版只提供站内通知和未读数。事务 outbox 只保存资源/版本/任务 ID、事件类型、操作者和时间，不保存标题、正文、问题或摘要；投递通过 ACL 后才生成并保存安全摘要。

通知投递创建记录前先校验接收者当前 ACL；已撤权事件直接丢弃且不保存敏感摘要。打开通知时再次校验权限：

- 有权限：进入对应版本、反馈或任务。
- 无权限：显示“资源已不可访问”，不展示旧摘要。

相同资源短时间内多次更新合并为一条通知；管理员批量迁移不向 400 人发送数百条重复事件。

## 8. 个人历史

统一索引当前用户自己的：

- 对话和问题。
- 打开的逻辑文档。
- 执行的跨文档比较。
- 结构化数据查询。
- 提交的反馈。
- 使用过的场景助手。

历史搜索只返回当前用户记录，并在读取关联资源时重新执行 ACL。历史中不复制业务正文，仅保存必要标题、时间、动作和原记录引用。

用户可以：

- 按时间、类型、知识库和助手筛选。
- 继续对话。
- 重新运行问题。
- 删除自己的历史展示记录。

删除个人历史不删除企业审计、负责人任务或文档访问事件；UI 明确区分“个人历史”和“企业审计”。

## 9. 快捷入口

快捷入口来源：

- 用户置顶助手。
- 用户收藏问题。
- 管理员为全员配置的入口。
- 文件负责人为知识库配置的入口。

优先级为用户置顶、角色可见的企业入口、最近使用。快捷入口不保存额外权限，执行时仍使用当前用户身份。

管理员不能把严格受限助手推送给没有对应能力的员工；不可用入口直接不返回，而不是显示后再报错。

## 10. 数据模型

建议新增：

- `favorite_items`
- `subscriptions`
- `notifications`
- `user_activity`
- `curated_questions`
- `popular_question_snapshots`
- `user_home_preferences`

统一要求：

- 业务资源使用逻辑 ID，不保存物理路径。
- 所有用户对象以 `user_id` 分区。
- 通知和活动写入使用幂等事件键。
- 聚合任务记录统计窗口和权限快照版本。

## 11. API

建议：

- `GET /experience/home`
- `GET /experience/search-suggestions?q=`
- `GET/POST/DELETE /favorites`
- `GET/POST/DELETE /subscriptions`
- `GET /notifications`
- `PUT /notifications/{id}/read`
- `PUT /notifications/read-all`
- `GET/DELETE /history`
- `GET/POST/PUT/DELETE /knowledge-bases/{kb_id}/curated-questions`
- `PUT /experience/home-preferences`

所有列表分页。首页 API 可以并行聚合，但每个区块返回独立状态，避免一个慢查询阻塞全部。

## 12. 隐私与统计

- 常问问题按不同用户数聚合，不按单个用户重复次数刷高。
- 聚合前过滤敏感问题。
- 不展示个人提问排行榜。
- 不用员工行为推断绩效。
- 不把私人历史交给其他员工或负责人。
- 管理员只能通过企业审计查看受控事件，不能进入员工个人历史页面冒充本人。

## 13. 缓存

建议和首页可以缓存，但缓存必须包含：

- 用户 ID。
- 用户权限版本。
- 资源版本。
- 助手配置版本。

权限变化发布失效事件。缓存只保存资源 ID 和安全标题，不保存无权限正文。不得恢复已禁用的最终答案缓存。

## 14. 失败处理

- 建议服务失败：输入框仍可正常发问。
- 热门统计失败：隐藏“大家常问”，保留负责人推荐问题。
- 通知投递失败：事件保留待重试，不影响文档版本提交。
- 关联资源不可访问：返回稳定的 unavailable 状态。
- 首页某区块超时：其他区块照常显示。
- 重复点击收藏或已读：幂等成功。

## 15. 测试

必须覆盖：

- 搜索建议不出现无权限文件和知识库。
- 权限撤销后缓存建议立即失效。
- 低于不同用户阈值的问题不公开。
- 敏感问题不进入热门统计。
- 收藏旧答案能提示新版本。
- 权限撤销后收藏不泄露旧摘要和下载 URL。
- 通知聚合和幂等。
- 打开旧通知重新校验 ACL。
- 个人历史只属于当前用户。
- 删除个人历史不删除审计事件。
- 首页区块部分失败时可用。
- 快捷入口不能扩大权限。
- 站内通知未读数并发更新正确。

## 16. 完成标准

- 员工能在首页两次点击内回到最近工作或常用助手。
- 建议、收藏、通知和历史全部服从当前权限。
- 文件更新能触达真正订阅者，而不会形成通知风暴。
- 员工能够区分“我的历史已删除”和“企业审计仍按规则保留”。
