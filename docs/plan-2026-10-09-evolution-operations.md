## 0. 目标与红线

**目标**：把系统从"受控实验"推进到"常态化运转"——即：真实失败进来 → 自动产出可审的制品
（诊断 / 候选 / 工单 / 补丁）→ 门禁过滤 → 人工一键裁决 → 结果可复测。

**红线（不因任何"提效"而放宽）**：

1. **系统永不自动应用、永不自动合入**：层 4 之后一律是人的动作；前端只提供"复制命令/下载补丁"。
2. **门禁阈值不放宽**：路由 ≤0pp、Top-5 ≤2pp、开发集 ≥80%。
3. **补丁不得触碰** `tests/**`、`config.py`、`rag/evolution/**`、`scripts/**`、`frontend/**`。
4. **无证据不改**：任何改动都要有可复现的判据；实测无效就撤回并留档（本项目已有三次先例）。
5. **不把"机制能跑"当成"能力成立"**：区分"契约修好"与"判断正确"、"演示一次"与"稳定运转"。

## 2. 执行队列（按顺序）

每项都写：**为什么做 / 改哪里 / 验收判据（先注册）/ 成本 / 明确不做**。

### 队列 1：Worker 运行化（对应其他 agent 的"维度三"前半）

- **为什么**：候选生成（Phase 4）与补丁生成（Phase 5）**没有接进 worker**，现在必须人工跑脚本；
  这是"常态化"的最小缺口。
- **改哪里**：`rag/evolution/worker.py` 增加**候选/补丁生成步骤**（复用现有 step 工厂模式）；
  只处理"聚类已批准 + `confirmed_layer` 已确认 + 该观测尚无对应候选"的项；每次模型调用**计入预算**；
  新增配置：`evolution_candidate_model_calls`（现为死配置，只有定义没有读取点）、每次轮次的
  候选/补丁上限；预算与窗口按时间可配（低峰提额）。
- **验收判据（先注册）**：① 在临时库上，一轮 worker 能对合格聚类**自动产出候选/补丁**并落库
  （用例钉住"不合格的不动、预算不超、不变量不破"）；② 现有红线与既有 1923 条用例全绿；
  ③ 真实库上跑一轮，确认它**只处理合格项**（当前应无合格项 ⇒ 0 产出，且不误伤）。
- **成本**：代码 + 用例为主；真实跑一轮的模型调用按 3–5 次计。
- **明确不做**：**不引入异步任务队列/并发编排**（单线程轮询 + 空转现状下，并发风险远大于收益）。

### 队列 2：Agent 路径加固（用户批准项）

- **为什么**：`rag/agent.py` 里同时装着 **Agent 模式（`RAGAgent` 工具循环）** 与 **路由器**
  （`route_question`，被知识库旧链路调用）。已合入的 #10 只加固了**路由器**；Agent 路径本身是否
  存在同类"注释声称 fail-closed、代码却没兜"的错配，**尚无证据**。
- **改哪里**：先做**证据检查**（审计 Agent 路径的模型调用/工具调用失败语义与注释承诺是否一致）；
  - 若发现错配 ⇒ 按 #10 的同一手法修 + 用例（异常必须 fail-closed 或返回可解释状态）；
  - 若无错配 ⇒ **如实记录"无据可修"**，改为把 **Agent 路径的失败纳入观测**（需要真实流量，
    属队列 7 的前置），不盲改。
- **验收判据**：一份审计结论（含逐处引用的代码位置）；有改动则以用例钉住行为；无改动则写明依据。
- **成本**：审计为主；有改动时 1 次实现 + 用例。

### 队列 3：标签覆盖 + 无标签护栏（原 #3）

- **为什么**：标签是**唯一被实测证明高产出**的杠杆（带标签族 **1/4 → 4/4 且两轮稳定**，
  §13–§15）；而失败供给里可标注只有 5.5%。
- **改哪里**：① 继续按**证据**补管理员标签（每条注明语料出处，沿用 §12 的复核方式）；
  ② 加"无确定性证据"护栏：当失败既无标签、又无确定性命中/缺失信号时，草案**显式标注"需要管理员
  标签才能定性"**，而不是给出一个看起来确定的 `undetermined`。
- **验收判据**：带标签流程在 **N ≥ 8 条**上达到多数票一致率目标（先注册具体数值）；护栏行为有用例；
  无标签协议（40 行）不低于本底噪声（±2 行）。
- **成本**：标签是人工数据工作（我做，需你抽检）；护栏是小改动 + 用例。

### 队列 4：AST 符号索引 + 靶心窗口（其他 agent 的"维度二"，采纳其核心）

- **为什么**：中文诊断 → 关键词排序**退化为字母序**（今日验收实测："无帧"首目标是
  `rag/bm25_store.py`，纯属猜）；`exception_frame` 只解决异常类失败，**逻辑缺陷仍无事实定位**。
- **改哪里**：① 为 `rag/**` 白名单模块建 **AST 符号表**（类/函数/签名/docstring/调用关系）；
  ② 诊断草案增加 `suggested_symbols`（**必须对着符号表做确定性校验**，不合法即丢弃）；
  ③ 生成器用"帧 → 符号 → 文件"定位，并把**靶心窗口**（目标函数/行 ±N 行）作为上下文，
  **总提示词预算封顶**。
- **验收判据**：以 cluster #30 的真实缺陷为靶——生成器的**第一个目标文件**必须是含该符号的文件
  （确定性检查）；再一次真实生成，观察 diff 是否落在正确函数（信息性，不作通过条件）。
- **成本**：中等（AST 索引 + 生成器接线 + 用例）；真实生成 3–5 次调用。
- **明确不做**：**不把每文件截取放宽到 1200–1500 行**（提示词已 30k 字符、每次推理 5–10k token）；
  **暂不做两阶段（Plan→Diff）**——先看符号定位是否已足够。

### 队列 5：知识缺口工单（其他 agent 的"维度一"，最高业务价值）

- **为什么**：78% 的失败是**知识库缺资料**，而现有执行器只有"改 Prompt/改代码"；这批失败
  现在停在观察队列里**没有出口**（`clusterer.py:125-126`：undetermined 永不离开队列，设计 §6）。
- **改哪里**：新增第三种制品 **`knowledge_gap_ticket`**，走**独立队列**（**不得**放松
  "undetermined 不进候选池"这条不变量）；诊断阶段自动起草：同义问法、触发频次、缺失的实体/型号/
  事实、建议归属库；与既有材料入库管线联动（`rag/materials/`）；前端提供"知识补充"入口；
  入库后反查相关观测 → 批量推进 → **复测验收**。
- **验收判据**：不变量仍被用例钉住（undetermined 不进候选池）；对现有内容缺口观测能产出工单
  （数量与字段可见）；工单闭环的**入库后复测**有可走通的路径（人工内容到达后能验证）。
- **成本**：设计与实现中等；**变现依赖人工补内容**。

### 队列 6：沙箱 Golden Fixture（其他 agent 的"维度四"）

- **为什么**：沙箱剥掉所有 `RAG_*`（含凭据），而嵌入/重排都是外部调用 ⇒ 层 2 在沙箱内**永远
  无法自动化**（今天已把回归 A/B 脚本化到宿主，见 §5.2）。本项目文档 §7 早写明该方案。
- **改哪里**：在**有凭据环境**一次性录制四个 seam（路由决策、改写文本、query 向量、重排顺序），
  沙箱内注入只读 Mock 适配器重放；**fixture 必须版本化**，检索路径变更即重录。
- **验收判据**：沙箱内对一份已存补丁**无需凭据**产出 `benchmark` 结论（不再是 "replay unavailable"）；
  且存在"fixture 过期 ⇒ 判为不可用"的守卫（绝不让过期 fixture 伪装成通过）。
- **成本**：中等；录制需要一次带凭据的批量运行。
- **风险（必须写进文档）**：录制数据与代码/语料漂移会让门禁**说谎**。

### 队列 7：前端代码补丁审查台（其他 agent 的"维度五"）

- **为什么**：后端只读端点已齐（`code-generation-queue`、`code-candidates/{id}`、门禁轨迹），
  前端没有对应页签，管理员只能看 JSON。
- **改哪里**：自进化中心增加"代码补丁"页签：diff 视图、沙箱/测试结论、门禁轨迹、
  **仅复制**的 apply/revert 命令、补丁下载、A/B 指标展示。
- **验收判据**：页签能对着现有只读端点渲染（前端构建 + 组件测试）；**不出现任何执行入口**。
- **成本**：前端为主；优先级最低。

### 前置（不是我能做的）：真实失败供给

**没有真实流量，1–7 全都只是"能跑"**：worker 现在每轮 `scanned=0`（实测日志），任何自动化都
无事可做。这是唯一需要你提供的外部输入——对接真实使用，或指定一个持续产生真实失败的来源。

#### 2b：把 Agent 路径的失败纳入观测（已完成）

**问题**（发现 3）：agent 分支在检索前返回，既不产生 `insufficient_evidence` 决策，也不经过
`_record_stream_failure` ⇒ **零观测**，回路对这条路径完全盲。

**做法**：`RAGAgent.run(..., failure_reporter=None)`——降级时以异常对象调用回调；回调自带
try/except，**上报失败绝不影响答复**。`pipeline._agent_run_kwargs(prepared, *, pipeline, start_time)`
**总是**接上回调（两处调用点共用它：同步 911、流式 1016），回调内容就是
`pipeline._record_stream_failure(question, start_time, prepared, error)`——**复用与流式失败完全相同的
那条路径**：写 `ExecutionTrace(route="error")`，再按既有分类提交观测（内部缺陷 → 观测，带
`exception_class` + `exception_frame`；超时/限流 → `TRANSIENT_EXTERNAL` 跳过 ✓ 不污染观测池）。

**验收**：3 条新用例——降级时回调被调用（拿到异常对象）；回调自身抛错时答复仍然正常；pipeline
的回调确实提交观测（`route="error"` + `exception_class` + `exception_frame` 指向真实帧、无 transient
标记）。另适配了"向后兼容"那条断言：它的意图是**不出现权限 kwargs**，现在断言 `user`/`kb_id` 缺席
而 `failure_reporter` 在场。Agent 相关套件 15 passed。

#### 精度过滤已落地（2026-10-09）

**先取证，结论改变了做法**：那 4 条"不是缺陷"的观测与**确认为内容缺口**的观测**形态完全相同**
（`route=fixed` + `answerability=insufficient_evidence` + `chunks=0`，见 obs#11/#52/#53/#61 vs
obs#79–83）⇒ **任何基于路由/可答性/分数/哈希的过滤器都分不开它们**。而现有安全 guard
（`rag/guard.py`，prompt-injection 模式表）**也不拦这些**（它们不是注入，是**越权披露请求**）。
唯一能分开的是**人工判定**。因此没有采用"扩展 guard 模式"（会改变线上行为、且是可无限枚举的启发式），
而是把它做成**管理员判定**：

* 标签文件新增可选字段 **`"verdict": "not_a_defect"`**（出厂文件里已标 4 条，每条带 `admin_note`
  说明为什么"拒绝是正确行为"）；
* 新模块 `rag/evolution/verdicts.py`（纯函数、不写盘）：`load_verdicts` / `not_a_defect_questions`
  / `is_not_a_defect` / `filter_defects`，**只认 `not_a_defect` 一个值**——拼错的 verdict 一律忽略，
  绝不让笔误悄悄让真实缺陷静默；缺文件/坏 JSON 都退化为"没有判定"，与引入之前行为一致；
* **三个会产出制品的步骤**（诊断、问题集候选、代码补丁）都先过滤：被标记的问题**零模型调用**跳过。

**验收**：`verdicts` 模块 5 条用例（含"出厂文件必须真的标着那 4 条"的防回退断言）；worker 侧 1 条
用例（标记的零调用跳过，**同批未标记的照常生成** ⇒ 过滤是定向的而非一刀切）。**队列 5 的前置至此
满足。**

而不是把不可标注的问题硬写成标签。

### 队列 4 记录（AST 符号索引 + 靶心窗口，`patch-v3`）

**问题**（实测）：生成器按"诊断措辞在文件里出现的次数"排序文件。中文诊断贡献的是**中文二字组**，
在英文代码路径里命中率为 0 ⇒ 排序退化为**文件字母序**，于是证据边界的缺陷产出了三份改
`rag/agent.py` 的补丁。`exception_frame` 只解决了异常类失败，**逻辑缺陷仍然没有事实定位**。

**新增 `rag/evolution/symbols.py`**（纯函数、无缓存、不写盘）：

* `SymbolIndex.build(root, files)`：用 `ast` 解析出每个类/函数/方法及其行区间（实测 143 文件 →
  1696 符号，约 1.5s；相比它服务的模型调用可忽略）。**读不了/解析不了的文件直接跳过**——索引是
  生成的辅助，不是它的门禁。
* `locate(name)`：`rag.retriever.Retriever._rrf_fuse` / `Retriever._rrf_fuse` / `_rrf_fuse()` 都能
  解析；歧义按 `(path, start)` 取第一个（同输入必得同结果）。
* `symbols_in_text(text)` / `files_in_text(text)`：文本里出现**且真实存在**的标识符 → 符号/文件，
  按首次出现顺序、每文件一个、上限 4 ✓ **虚构标识符与纯中文不产生噪声**。
* `window_excerpt(text, center=…)`：以目标行为中心、至多 `BULLSEYE_MAX_LINES=400` 行的**靶心窗口**
  （文件本身不超过 400 行则整篇返回）。

**接线（`patch_generator.py`）**：`generate` 建索引 → 从观测读帧的**文件与行号**、从诊断文本解析
**点名的真实符号** → 二者作为"聚焦目标"（事实）排在关键词排序之前 → 聚焦文件用**靶心窗口**取正文，
其余文件沿用原"前 400 行"，并在渲染头上说明**显示的是哪一段** → 另加一段**定位块**放在正文之前
（异常帧 + 诊断点名的符号及其行区间）。提示词版本 `patch-v2 → patch-v3`。
