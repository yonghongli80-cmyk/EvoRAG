文件：`real-cases-v1-draft.json`。这是待管理员确认的输入与标签草稿，不是系统回放报告。

## 来源与筛选

- 来源为本机企业知识库 `data/runtime/state/runtime-state.sqlite3` 中的钉钉问答审计，只读查询。
- 仅选消息 ID 符合钉钉实际消息格式 `msg...` 的记录：48 条、12 个提问账号、39 个去重问题，时间为 2026-09-03 至 2026-09-10。
- 另有 978 条 `speech-*` 验收消息，未混入真实消息集。该筛选能排除已知验收 ID，但不能证明 48 条消息均为自然业务流量，可能包含人工试问。
- 草稿收入 26 条，排除 13 条寒暄、能力介绍、依赖个人实时权限的文件夹问题、纯公开百科问题或文件发送请求。
- 收入的问题按审计原话保留；未写入提问人 ID、消息 ID、审计原文答案、文件路径和内部系统地址。

## 标签状态

- `case_id` 为本次整理分配的稳定编号。不要在后续修改已有编号。
- `category` 只描述问题形态；`ordinary` 不代表已验证有正确答案。
- `expected_route` 中只有两个信息明显不足的问题先标 `clarification`；其余为 `unknown`。目标 RAG 的路由和知识库结构尚未提供，不能根据当前系统实际路由推断其期望路由。
- `kb_id` 均为 `unknown`；`expected_source_names` 和 `expected_answer` 未填写。管理员应依据目标项目的固定知识库逐条确认。
- 本文件没有执行轨迹、失败根因、聚类或伪造的回放结果。需要在目标 RAG 上真实回放后另行生成。

## 入库前必须确认

1. 将每条 `kb_id` 映射到目标项目的真实知识库 ID。
2. 对照目标知识库确认 `expected_route`、正确来源和 1～3 句 `expected_answer`；无法确认的继续保留 `unknown`。
3. 对价格、物流、退换货、岗位制度等可能变动的内容确认适用版本和日期。
4. 若目标系统的路由只接受 `rag`、`structured`、`tool`、`clarification`，先完成 `unknown` 标签复核再入库。
5. 固定知识库后进行真实回放；无法复现的案例按指南排除，失败案例不要为美化报告而改标签。
